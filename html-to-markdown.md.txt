Clase 08 · Segundo corte

Arreglos, objetos  
y módulos
=============================

Cómo organizar los datos del proyecto y separar el código en archivos.

Robert Garcia ReyDesarrollo Web · EAM 2026-II

De un dato a una colección
--------------------------

En la clase anterior guardamos valores en variables. Un proyecto real necesita representar **muchos registros**: libros, rutinas, lugares o solicitudes.

Un **objeto** reúne las características de un registro. Un **arreglo** reúne varios registros y conserva su orden. Juntos permiten trabajar con datos del proyecto antes de conectarlo a una API.

  Ejemplo

Referencias: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Indexed\_collections y https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Working\_with\_objects.

¿Qué es un arreglo?
-------------------

Un **arreglo** guarda varios valores bajo un mismo nombre. Se escribe entre corchetes `[]` y las comas separan sus elementos. Por ejemplo, `categorias` puede contener los textos Novela, Ciencia e Historia.

Los elementos conservan un orden y cada uno ocupa una posición. Podemos leer una posición o recorrer toda la colección. Un arreglo vacío, `[]`, representa una colección que todavía no tiene elementos.

JavaScript permite mezclar tipos, pero un catálogo resulta más fácil de consultar cuando sus elementos son **objetos con las mismas propiedades**.

  Ejemplo

Referencia: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Indexed\_collections.

Índices y longitud
------------------

El **índice** es el número de una posición. Empieza en `0`: `categorias[0]` lee el primer elemento y `categorias[1]` lee el segundo.

`length` indica cuántas posiciones tiene el arreglo. En una lista de tres elementos, los índices son 0, 1 y 2. Su longitud es 3 y su último índice es `length - 1`.

Una posición inexistente devuelve `undefined`, es decir, allí no hay un valor. Si la colección está vacía, comprobamos `length` antes de intentar usar sus elementos.

  Ejemplo

Referencia: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Indexed\_collections.

Agregar y quitar elementos
--------------------------

`push(valor)` agrega un elemento al final y devuelve la nueva longitud. `pop()` retira el último elemento y devuelve ese valor. En un arreglo vacío, `pop()` devuelve `undefined`.

Ambos **modifican el arreglo original**. Después de llamar al método, la misma colección tiene un contenido diferente.

`const` impide reemplazar el arreglo mediante otra asignación, como `categorias = []`. Sí permite agregar o retirar elementos del arreglo que ya tenemos.

  Ejemplo

Referencias: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global\_Objects/Array/push y https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global\_Objects/Array/pop.

Recorrer con for...of
---------------------

`for...of` repite un bloque de instrucciones para cada valor del arreglo. En cada vuelta, una variable recibe el **elemento actual**, siguiendo el orden de la colección.

En `for (const titulo of titulos)`, `titulos` es la lista completa y `titulo` contiene un texto a la vez. Primero vale El principito, después La vorágine y luego Sapiens.

El bloque entre llaves se ejecuta una vez por elemento. Con `[]` no se ejecuta. Esta forma entrega los valores, no los números de sus posiciones.

  Ejemplo

Referencia: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Statements/for...of.

¿Qué es un objeto?
------------------

Un **objeto** agrupa datos que describen una misma entidad. Dentro de las llaves escribimos pares **propiedad: valor**.

Un libro puede tener `id`, `titulo` y `disponible`. Cada propiedad responde una pregunta diferente sobre ese libro. El valor puede ser de distinto tipo: número, texto, booleano, arreglo u otro objeto.

  Ejemplo

Referencia: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Working\_with\_objects.

Leer propiedades
----------------

El **punto** permite leer una propiedad por su nombre: `libro.titulo` obtiene el título. También podemos escribir `libro['titulo']`.

Los **corchetes** evalúan lo que hay dentro. Si `campo` contiene el texto `'disponible'`, `libro[campo]` consulta la propiedad disponible. En cambio, `libro.campo` busca literalmente una propiedad llamada campo.

Una propiedad inexistente devuelve `undefined`. Revisen el nombre escrito y recuerden que las mayúsculas y minúsculas importan.

  Ejemplo

Referencia: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Working\_with\_objects.

Actualizar un objeto
--------------------

Una asignación como `libro.disponible = false` cambia una propiedad. Si escribimos `libro.autor = 'Ana'` y autor no existía, agrega esa propiedad. Con `const`, las propiedades **siguen siendo modificables**.

`const mismoLibro = libro` hace que ambos nombres señalen el mismo objeto. No crea una copia independiente. Si cambiamos disponible desde libro, al leerlo desde mismoLibro también obtenemos el nuevo valor.

Ese vínculo se llama **referencia**. Conviene reconocerlo para evitar cambiar un registro compartido sin darse cuenta.

  Ejemplo

Referencia: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Working\_with\_objects.

Arreglos de objetos
-------------------

Un **arreglo de objetos** representa varios registros. El arreglo contiene la colección y cada objeto describe uno de sus elementos mediante propiedades como id, título y género.

`libros[1].titulo` combina las dos estructuras: primero selecciona el segundo objeto del arreglo y después lee su título.

El `id` identifica el registro. El **índice** indica su posición actual. Al reordenar la lista, la posición puede cambiar y el id mantenerse. Por eso buscamos registros por su identificador.

  Ejemplo

Referencias: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Indexed\_collections y https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Working\_with\_objects.

Una función dentro de un método
-------------------------------

Los métodos que siguen reciben una **función como argumento**. JavaScript la llama con un elemento del arreglo a la vez. Esa función suele llamarse **callback**.

En `function (libro)`, libro es un parámetro. Recibe el primer objeto en una llamada, el segundo en la siguiente y así sucesivamente. Su nombre lo elegimos nosotros.

En `find` y `filter`, `return` responde si el elemento cumple la condición. En `map`, devuelve el valor transformado. Una función que solo escribe en consola no devuelve automáticamente lo que mostró.

  Ejemplo

Referencia: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global\_Objects/Array/forEach.

Recorrer con forEach
--------------------

`forEach` ejecuta una función por cada elemento del arreglo. El parámetro `libro` recibe un objeto diferente en cada llamada. Dentro de la función podemos leer sus propiedades.

Sirve para realizar una acción con todos los registros, por ejemplo, escribir cada título en consola. Con un arreglo vacío, no llama a la función.

El método devuelve `undefined`. Guardar el resultado de `forEach` en una variable no crea una lista nueva, aunque la función haya mostrado todos los títulos.

  Ejemplo

Referencia: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global\_Objects/Array/forEach.

Encontrar un registro con find
------------------------------

`find` devuelve el **primer elemento** que cumple una condición. Para cada elemento, la función devuelve `true` si coincide y `false` si debe seguir buscando.

`return libro.id === 2` pregunta si el libro actual tiene id 2. Cuando encuentra uno, `find` devuelve ese objeto y termina la búsqueda.

Si ninguno coincide, devuelve `undefined`. Antes de usar `encontrado.titulo`, comprobamos que exista un resultado. Así podemos mostrar un mensaje en vez de provocar un error.

  Ejemplo

Referencia: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global\_Objects/Array/find.

Filtrar con filter
------------------

`filter` revisa todos los elementos y devuelve un **arreglo nuevo** con los que cumplen la condición. Cada `true` incluye el elemento y cada `false` lo deja fuera del resultado.

Una coincidencia produce un arreglo con un elemento. Ninguna coincidencia produce `[]`. Para saber si hay resultados, consultamos la longitud del arreglo devuelto.

La colección original conserva sus elementos. Los objetos del resultado son los mismos, no copias independientes. El filtro selecciona registros sin eliminarlos del original.

  Ejemplo

Referencia: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global\_Objects/Array/filter.

Transformar con map
-------------------

`map` devuelve un **arreglo nuevo** con un resultado por cada elemento original. La función transforma el elemento y usa `return` para indicar qué valor guardar en la nueva posición.

Si devolvemos `libro.titulo`, convertimos una colección de objetos en una lista de textos. Dos libros producen dos títulos. Con `[]`, el resultado también es `[]`.

Este ejemplo conserva los objetos originales porque solo lee sus títulos. `map` no evita cambios si escribimos instrucciones que modifiquen los objetos dentro de la función.

  Ejemplo

Referencia: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global\_Objects/Array/map.

Qué devuelve cada método
------------------------

### forEach

Ejecuta una acción con cada elemento. Devuelve `undefined`.

### find

Devuelve el primer elemento que cumple la condición, o `undefined` si no hay coincidencias.

### filter

Devuelve un arreglo con todas las coincidencias. Sin coincidencias, devuelve `[]`.

### map

Devuelve un arreglo con un valor transformado por cada elemento original.

Para elegir, definan qué necesitan obtener: una acción, un registro, una selección o una transformación.

Referencia: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global\_Objects/Array.

¿Para qué sirven los módulos?
-----------------------------

Los **módulos** permiten repartir el código en archivos con responsabilidades claras. Por ejemplo, `datos.js` contiene un catálogo y `app.js` usa esos datos para responder a la interfaz.

Cada módulo tiene su **propio ámbito**, es decir, un espacio donde existen sus variables. Una variable declarada en un módulo no queda disponible automáticamente en otro.

Para compartirla usamos `export` y `import`. En el ejemplo, dos módulos declaran mensaje con valores diferentes y cada uno conserva el suyo.

 Ejemplo

Los dos módulos declaran mensaje sin compartir ni sobrescribir sus variables. El ámbito pertenece a cada módulo. Para practicar archivos separados, consultar ejemplo\_modulos. Referencias: https://www.jscamp.dev/javascript/modulos-javascript y https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules.

Compartir código con export e import
------------------------------------

En `datos.js`, `export const titulo = 'El principito'` declara el dato y permite que otro módulo lo use.

En `app.js`, `import { titulo } from './datos.js'` permite usar ese dato. Las llaves indican una **exportación nombrada**. El nombre titulo debe coincidir y `./` significa «en la misma carpeta».

El ejemplo abre en JSFiddle. Sus comentarios distinguen el código de cada archivo y la preparación necesaria para ejecutarlo allí. En el proyecto crearán los archivos reales.

 Ejemplo

En JSFiddle, el import map asigna la ruta ./datos.js a un pequeño módulo data: que exporta titulo. El ejemplo funciona sin publicar archivos. En el proyecto, crear datos.js real. Referencias: https://www.jscamp.dev/javascript/modulos-javascript y https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules.

Ejecutar módulos en el navegador
--------------------------------

El HTML carga el archivo principal con `<script type="module" src="./app.js"></script>`. `src` indica el archivo y `type="module"` permite usar importaciones.

El navegador carga app.js y los módulos que este importa. Los módulos de esta clase esperan a que el navegador termine de leer el HTML antes de ejecutar su código. Así pueden encontrar los elementos de la página.

En JSFiddle escribimos el módulo dentro del panel HTML. En el proyecto, ese mismo código estará en app.js y abriremos la página con Live Server.

 Ejemplo

JSFiddle ya sirve la página mediante web; el ejemplo coloca el módulo antes del botón para demostrar la ejecución diferida. Para el proyecto con archivos separados, usar Live Server. Referencias: https://www.jscamp.dev/javascript/modulos-javascript y https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules.

Live Server y los archivos locales
----------------------------------

Al abrir index.html con doble clic, el navegador usa una dirección `file:///C:/...`. Lee un archivo del computador. Ese modo puede bloquear la carga de otros archivos mediante `import` por seguridad.

**Live Server** sirve los archivos como una página web desde tu propio computador. La dirección será, por ejemplo, `http://127.0.0.1:5500/`. Es una dirección local y no publica tu proyecto en internet.

En VS Code, abre la carpeta del proyecto. Con Live Server instalado, haz clic derecho en index.html y elige **Open with Live Server**. Comprueba que la dirección empiece por http, no por file.

127.0.0.1 y localhost identifican el equipo local. 5500 es un puerto habitual, pero puede cambiar. Live Server entrega archivos estáticos y no requiere programar un backend. En JSFiddle no hace falta este paso. Referencias: https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Modules y https://github.com/ritwickdey/vscode-live-server.
